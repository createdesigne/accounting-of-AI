# AI Thought Receipt Bridge（Chrome拡張機能）

表示中のAI会話を「私とAIの確定申告」へ渡し、確認・修正してから思考レシートとして保存できます。

## インストール・更新

1. サイトの「レシート」画面下部から「Chrome拡張機能をダウンロード」を押します。
2. ZIPを展開します（Windowsは右クリック→「すべて展開」）。
3. Chromeで `chrome://extensions/` を開き、「デベロッパーモード」を有効にします。
4. 「パッケージ化されていない拡張機能を読み込む」から、展開した `ai-thought-receipt-bridge` フォルダーを選択します。
5. 導入済みの場合は、元のフォルダーのファイルを更新版で置き換え、Chromeの拡張機能管理画面で再読み込みします。別フォルダーへ入れる場合は古い拡張機能を削除し、重複させないでください。ブラウザーに保存した帳簿データには影響しません。

## 使い方

1. ChatGPT・Claude・Geminiなどの会話ページで、本文を表示します。
2. 拡張機能を開き、送信先を確認して「思考レシート化する」を押します。既定は本番サイトです。
3. Webアプリで候補の内容を確認・修正し、「レシートを発行する」→「帳簿に保存する」を押します。取り込みだけでは帳簿に保存しません。

送信先は本番（https://accounting-of-ai.vercel.app/accounting-of-AI/）、研究用Vercel Preview（`https://accounting-of-ai-git-feature-research-mvp-accounting-of-ai.vercel.app/accounting-of-AI/`）、旧サイト（GitHub Pages）、確認用プレビュー、ローカル開発用（`http://localhost:5173/accounting-of-AI/`）、研究用ローカル（`http://localhost:5174/accounting-of-AI/`）から選べます。プレビューの帳簿は本番と別です。研究用統合環境は `pnpm dev -- --port 5174` で起動してください。研究用Vercel PreviewがVercelの認証画面へ移動する場合は、同じChromeプロファイルでログインし、Previewのアプリ画面へ戻ってから拡張機能とタブを再読み込みしてください。

研究用ローカルで会話と実測時間を対応させる場合は、活動計測を開始したまま会話の「思考レシート化」を実行し、その後に計測停止と「帳簿へ連携」を行ってください。会話にはその時点の計測セッションIDだけが付与されます。週次画面は同じセッションIDの確定時間を候補にしますが、保存前の本人確認は省略しません。候補が複数または見つからない場合は推測せず、本人が選択します。

会話の取得はボタンを押したときだけ行います。画面に読み込まれた直近20メッセージを対象とし、サイト側の表示変更・未読み込み・ログイン状態によっては取得できません。空の会話をサンプルデータで補うことはしません。

## ChatGPT利用時間の計測（v0.4.0）

計測は初期状態では停止しています。拡張機能を開いて「計測を開始」を押した後に限り、ChatGPT（`chatgpt.com` または旧 `chat.openai.com`）のタブで利用者が操作した時間を記録します。「計測を停止」を押すと、その場で終了します。

- ChatGPTのタブが選択され、Chromeのウィンドウが手前にある場合だけ計測します。
- キー操作、クリック、スクロール、タッチを操作として扱います。最後の操作から5分までを利用時間に含め、5分を超えた部分は含めません。
- 別のタブへ移動した場合や、Chrome以外のウィンドウへ移動した場合は直ちに止まります。ChatGPTに戻った後、再び操作すると再開します。
- 記録は整数の秒数と活動IDを持ち、拡張機能の `chrome.storage.local` にだけ保存します。
- 操作があった事実だけを計測処理へ通知します。キーの内容、入力欄、会話本文、APIキーを取得・送信することはありません。

計測自体は端末内だけで行い、Gemini APIへの接続や月次決算との連携は行いません。Webアプリへの帳簿連携は、下記の手動操作または利用者が明示的にONにした自動取り込みの場合だけ行います。

### 確定済み利用時間の確認連携

拡張機能の「帳簿へ連携」を押すと、20分の無操作または手動停止で確定した日別の利用時間だけを、選択した「私とAIの確定申告」Webアプリへ渡します。Webアプリには件数と合計時間の確認画面が表示され、「会計に取り込む」を押した場合だけ、借方「AI仮受品」／貸方「時間拠出」の仕訳を秒単位で保存します。確認画面を表示しただけでは保存しません。

- 送信するのは記録ID、セッションID、サービス名、利用日、タイムゾーン、開始・終了時刻、利用秒数だけです。
- 会話本文、閲覧URL、タブID、入力内容、APIキーは送信しません。
- 送信先は本番、研究用Vercel Preview、旧サイト、確認用プレビュー、ローカル開発用の許可済みWebアプリに限定します。
- 同じ記録を再送しても、確認画面では記録IDを基準に1件として表示します。
- 時間会計は思考レシート帳簿とは別の保存領域を使い、保存確認後にだけ拡張機能側を取込済みにします。

### 利用時間の自動取り込み（v0.4.4）

Webアプリ側の「自動取り込み」は初期設定ではOFFです。利用者が明示的にONにした場合だけ、Webアプリを開いたときに、この拡張機能へ確定済み・未取り込みの利用時間を問い合わせます。手動の「帳簿へ連携」と確認画面も引き続き利用できます。

- 許可済みのWebアプリURLに挿入された拡張機能ブリッジだけが、拡張機能のバックグラウンド処理へ問い合わせます。
- 保存に成功して読み直せた記録だけを取込済みにします。保存または完了通知に失敗した記録は削除せず、次回のWebアプリ起動時に再試行します。
- 同じ記録IDは時間会計ストアと排他制御で重複を防ぎます。複数タブが同時に要求しても仕訳は1件です。
- 自動取り込みでも会話本文、閲覧URL、タブID、入力内容、APIキーは送信しません。

### Windowsアプリ切り替えの修正（v0.4.1）

ChatGPTを表示したChromeからメモ帳など別のWindowsアプリへ移った際に、外部アプリの利用時間が加算される問題を修正しました。Chromeのフォーカス変更通知に加え、定期処理と状態表示の前にも、対象のChromeウィンドウ・タブが実際にアクティブかを確認します。Chromeへ戻っただけでは計測を再開せず、ChatGPTを再び操作した時点から新しい活動として再開します。以前の記録はそのまま保持します。

### 計測開始直後の無操作時間の修正（v0.4.2）

ChatGPTを表示中に「計測を開始」を押した時点を最初の操作として記録します。その後6分間操作しなかった場合は、最初の5分（300秒）を保存し、5分を超えた1分は除外します。Manifest V3のバックグラウンド処理が停止・再起動しても、端末内に保存した最終操作時刻から同じ計算を再開します。また、バックグラウンド処理が起動するたびに定期確認用Alarmの存在を調べ、消えていれば作り直します。

### 拡張機能更新後の古いページ処理の修正（v0.4.3）

拡張機能を更新・再読み込みすると、更新前から開いていたChatGPTタブには古いcontent scriptが残ることがあります。この古い処理が無効な拡張機能コンテキストへメッセージを送ってエラーを繰り返さないよう、送信前にコンテキストを確認し、同期例外と非同期エラーの両方を処理します。無効を検出した古い処理は、自身が登録した操作監視をすべて解除して停止します。

更新後は既存のChatGPTタブを再読み込みしてください。Manifestで指定した新しいcontent scriptはページ読み込み時に挿入されるため、タブを再読み込みするまで新しい計測処理へ置き換わりません。

新しい送信形式は `#draft=...` です。会話本文をHTTPリクエストのURLに含めず、Webアプリが候補を作ったあと、アドレスバーからも取り除きます。既存の `?draft=...` 形式も引き続き読み込めます。

## AIごとの読み取り（v0.3.0）

- ChatGPT（旧 `chat.openai.com` を含む）：会話の話者属性からユーザー・AIを識別します。
- Claude：ユーザーメッセージと回答本文の専用要素を識別します。
- Gemini：質問・回答の専用要素を識別します。

サイトごとの処理に分け、画面内のメニューやコピー等の操作、非表示の会話、重なった本文要素の二重取得を除外します。同じ文を複数回送った場合は、それぞれを別の発言として順序どおりに残します。拡張機能に対応AIの説明を表示し、送信先の選択・確認と修正・レシート発行・帳簿保存の手順、送信するデータの項目はv0.2.0の仕様を維持しています。

Perplexity・NotebookLM・Copilotは、画面に話者を示す対応要素がある場合のみ試験的に読み取ります。記事の並びや文面から話者を推測する処理は行いません。対応要素がなければ取得失敗として表示します。

対象はページに読み込まれたテキストです。未読み込みの履歴、画像・添付ファイルの中身、別フレームや閉じたShadow DOMの内部は対象外です。回答の生成完了後に実行し、取り込んだ候補を確認してください。

代表的な画面構造を使ったブラウザーテストで検証しています。各サービスにログインした実画面での検証は未実施で、サイトの表示変更によって取得できなくなる場合があります。

## 「会話本文が見つかりません」の改善（v0.3.1）

- 最初のメイン領域が空・非表示でも、表示中の会話の話者マーカーを探します。ナビゲーション・メニュー・非表示の本文は取り込みません。
- ChatGPTでは既存の話者属性に加え、会話ターンに明示されたユーザー／AIの属性も読み取ります。記事の順番から話者を推測しません。
- 本文がまだない場合のみ、最大約1.2秒の範囲で表示を待って再確認します。空の会話・未送信の入力欄をレシート化することはありません。
- ポップアップにバージョンを表示します。取得できない場合はサービス名・バージョンと、会話を開く／回答の生成完了を待つ／ページを再読み込みする手順を表示します。

更新には、最新版ZIPを展開し、Chromeに読み込ませた元のフォルダーのファイルを置き換え、`chrome://extensions/` で拡張機能の再読み込み（↻）が必要です。ポップアップに「バージョン 0.5.11」が表示されることを確認し、開いているChatGPTタブとWebアプリも再読み込みしてください。v0.5.2では最後に選択した送信先を端末内へ保存し、計測中の今回時間と確定済み時間を分けて表示します。v0.5.3では当時のChatGPT発言外枠に対応し、v0.5.4ではChatGPTの2ドメインだけに必要最小限のサイト権限を追加しました。v0.5.5では実際のChatGPTで確認した `data-conversation-role` と直後の本文要素を使用して質問・回答を取得します。v0.5.6では、拡張機能の更新後に研究用アプリの受信処理が無効になった場合でも、localhost:5174に限って受信ブリッジを安全に再注入します。v0.5.7では、会計保存後のService Worker通知を再試行し、通知失敗時も元の計測記録を保持したままWebアプリから完了通知だけを再送できます。v0.5.8では、研究用タブが正しいURLへ読み込みを完了し、実効ホスト権限が確認できた後だけ送信・受信ブリッジの復旧を行い、失敗段階・対象URL・権限状態を表示します。v0.5.9では、自動連携がChromeに拒否された場合でも、同じ計測ID・日時・実測秒数を安全にコピーし、Webアプリの本人確認画面へ手動で渡せます。v0.5.10では研究用Vercel Previewを独立した送信先として追加し、本番・旧サイト・ローカルの設定を維持したまま会話と実測時間の両方を送れるようにしました。v0.5.11では会話本文の同一性とは別に取得単位のIDを付け、同じ会話を再取得した場合でも新しい未使用の実測時間を本人が確認して関連付けられるようにしました。

`manifest.json`、`background.js`、`activityTracker.js`、`timeRecordProtocol.js` は、Chromeへ読み込む同じフォルダー直下に必要です。配布ZIPを使う場合は、展開後の `ai-thought-receipt-bridge` フォルダー全体を使用し、一部ファイルだけを別フォルダーへコピーしないでください。既に計測記録がある場合は拡張機能を削除・再登録せず、Chromeが現在読み込んでいる同じフォルダーの全ファイルを置き換えてから再読み込みしてください。

### ChatGPTのサイトアクセス権限

この拡張機能が要求するサイト権限は、会話取得・計測用の `https://chatgpt.com/*` と `https://chat.openai.com/*`、研究用受信ブリッジの復旧に必要な研究用Vercel Previewのホストと `http://localhost:5174/*` だけです。「すべてのサイト」へのアクセス権限やVercel全体への権限は要求しません。権限エラーが現在発生している場合は、`chrome://extensions/` で「AI Thought Receipt Bridge」→「詳細」→「サイトへのアクセス」を開き、表示中のChatGPTサイトと選択した研究用アプリでのアクセスを許可してから、拡張機能と対象タブを再読み込みしてください。

拡張機能管理画面の「エラー」には更新前の履歴も残ります。v0.5.11のポップアップに失敗段階・対象URL・権限状態が出ていなければ、過去の記録である可能性があります。現在の状態は、拡張機能と会話タブ、研究用アプリのタブを再読み込みした後のポップアップ表示で確認してください。既存の計測時間や帳簿データは再読み込みでは削除されません。自動連携を復旧できない場合は「実測記録をコピー」を押し、研究用アプリのホームにある「実測記録の手動連携」へ貼り付けてください。コピーしただけでは会計へ保存されず、アプリで内容確認後に「会計に取り込む」を押す必要があります。

「会話取得を診断」は、スクリプト注入、話者要素、本文候補、抽出件数を段階別に表示します。診断結果には会話本文、URL、会話タイトル、未送信の入力内容を含めません。

## Vercel版への送信（v0.5.1）

既定の送信先はVercel版です。会話の取り込みと確定済み利用時間の連携の両方が、選択した送信先にだけ渡されます。以前の帳簿は旧サイトのブラウザ保存領域に残り、自動では移りません。以前の帳簿へ追加する場合は「旧サイト（以前の帳簿）」を選んでください。旧サイトにはVercel版のGemini中継APIは接続していません。

## 開発時

`chrome-extension` のファイルを変更したら、リポジトリ直下で `python3 scripts/package-extension.py` を実行して配布ZIPを更新してください。`python3 scripts/package-extension.py --check` で一致を確認できます。依存ライブラリの追加は不要です。
