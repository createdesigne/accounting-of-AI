# AI Thought Receipt Bridge（Chrome拡張機能）

表示中のAI会話を「私とAIの確定申告」へ渡し、確認・修正してから思考レシートとして保存できます。

## インストール・更新

1. サイトの「レシート」画面下部から「Chrome拡張機能をダウンロード」を押します。
2. ZIPを展開します（Windowsは右クリック→「すべて展開」）。
3. Chromeで `chrome://extensions/` を開き、「デベロッパーモード」を有効にします。
4. 「パッケージ化されていない拡張機能を読み込む」から、展開した `ai-thought-receipt-bridge` フォルダーを選択します。
5. 導入済みの場合は、元のフォルダーのファイルを更新版で置き換え、Chromeの拡張機能管理画面で再読み込みします。別フォルダーへ入れる場合は古い拡張機能を削除し、重複させないでください。ブラウザーに保存した帳簿データには影響しません。

## 使い方

1. ChatGPT・Claude・Geminiなどの会話ページで、本文を表示します。
2. 拡張機能を開き、送信先を確認して「思考レシート化する」を押します。既定は本番サイトです。
3. Webアプリで候補の内容を確認・修正し、「レシートを発行する」→「帳簿に保存する」を押します。取り込みだけでは帳簿に保存しません。

送信先は本番、確認用プレビュー、ローカル開発用（`http://localhost:5173/accounting-of-AI/`）から選べます。プレビューの帳簿は本番と別です。

会話の取得はボタンを押したときだけ行います。画面に読み込まれた直近20メッセージを対象とし、サイト側の表示変更・未読み込み・ログイン状態によっては取得できません。空の会話をサンプルデータで補うことはしません。

## ChatGPT利用時間の計測（v0.4.0）

計測は初期状態では停止しています。拡張機能を開いて「計測を開始」を押した後に限り、ChatGPT（`chatgpt.com` または旧 `chat.openai.com`）のタブで利用者が操作した時間を記録します。「計測を停止」を押すと、その場で終了します。

- ChatGPTのタブが選択され、Chromeのウィンドウが手前にある場合だけ計測します。
- キー操作、クリック、スクロール、タッチを操作として扱います。最後の操作から5分までを利用時間に含め、5分を超えた部分は含めません。
- 別のタブへ移動した場合や、Chrome以外のウィンドウへ移動した場合は直ちに止まります。ChatGPTに戻った後、再び操作すると再開します。
- 記録は整数の秒数と活動IDを持ち、拡張機能の `chrome.storage.local` にだけ保存します。
- 操作があった事実だけを計測処理へ通知します。キーの内容、入力欄、会話本文、APIキーを取得・送信することはありません。

これは端末内の計測機能だけです。Gemini APIへの接続、Webアプリの帳簿への転記、月次決算との連携は行いません。

### 確定済み利用時間の確認連携

拡張機能の「帳簿へ連携」を押すと、20分の無操作または手動停止で確定した日別の利用時間だけを、選択した「私とAIの確定申告」Webアプリへ渡します。Webアプリには件数と合計時間の確認画面が表示されます。この段階では仕訳を作成せず、帳簿への保存や拡張機能側の取込済み更新も行いません。

- 送信するのは記録ID、セッションID、サービス名、利用日、タイムゾーン、開始・終了時刻、利用秒数だけです。
- 会話本文、閲覧URL、タブID、入力内容、APIキーは送信しません。
- 送信先は本番、確認用プレビュー、ローカル開発用の許可済みWebアプリに限定します。
- 同じ記録を再送しても、確認画面では記録IDを基準に1件として表示します。

### Windowsアプリ切り替えの修正（v0.4.1）

ChatGPTを表示したChromeからメモ帳など別のWindowsアプリへ移った際に、外部アプリの利用時間が加算される問題を修正しました。Chromeのフォーカス変更通知に加え、定期処理と状態表示の前にも、対象のChromeウィンドウ・タブが実際にアクティブかを確認します。Chromeへ戻っただけでは計測を再開せず、ChatGPTを再び操作した時点から新しい活動として再開します。以前の記録はそのまま保持します。

### 計測開始直後の無操作時間の修正（v0.4.2）

ChatGPTを表示中に「計測を開始」を押した時点を最初の操作として記録します。その後6分間操作しなかった場合は、最初の5分（300秒）を保存し、5分を超えた1分は除外します。Manifest V3のバックグラウンド処理が停止・再起動しても、端末内に保存した最終操作時刻から同じ計算を再開します。また、バックグラウンド処理が起動するたびに定期確認用Alarmの存在を調べ、消えていれば作り直します。

### 拡張機能更新後の古いページ処理の修正（v0.4.3）

拡張機能を更新・再読み込みすると、更新前から開いていたChatGPTタブには古いcontent scriptが残ることがあります。この古い処理が無効な拡張機能コンテキストへメッセージを送ってエラーを繰り返さないよう、送信前にコンテキストを確認し、同期例外と非同期エラーの両方を処理します。無効を検出した古い処理は、自身が登録した操作監視をすべて解除して停止します。

更新後は既存のChatGPTタブを再読み込みしてください。Manifestで指定した新しいcontent scriptはページ読み込み時に挿入されるため、タブを再読み込みするまで新しい計測処理へ置き換わりません。

新しい送信形式は `#draft=...` です。会話本文をHTTPリクエストのURLに含めず、Webアプリが候補を作ったあと、アドレスバーからも取り除きます。既存の `?draft=...` 形式も引き続き読み込めます。

## AIごとの読み取り（v0.3.0）

- ChatGPT（旧 `chat.openai.com` を含む）：会話の話者属性からユーザー・AIを識別します。
- Claude：ユーザーメッセージと回答本文の専用要素を識別します。
- Gemini：質問・回答の専用要素を識別します。

サイトごとの処理に分け、画面内のメニューやコピー等の操作、非表示の会話、重なった本文要素の二重取得を除外します。同じ文を複数回送った場合は、それぞれを別の発言として順序どおりに残します。拡張機能に対応AIの説明を表示し、送信先の選択・確認と修正・レシート発行・帳簿保存の手順、送信するデータの項目はv0.2.0の仕様を維持しています。

Perplexity・NotebookLM・Copilotは、画面に話者を示す対応要素がある場合のみ試験的に読み取ります。記事の並びや文面から話者を推測する処理は行いません。対応要素がなければ取得失敗として表示します。

対象はページに読み込まれたテキストです。未読み込みの履歴、画像・添付ファイルの中身、別フレームや閉じたShadow DOMの内部は対象外です。回答の生成完了後に実行し、取り込んだ候補を確認してください。

代表的な画面構造を使ったブラウザーテストで検証しています。各サービスにログインした実画面での検証は未実施で、サイトの表示変更によって取得できなくなる場合があります。

## 「会話本文が見つかりません」の改善（v0.3.1）

- 最初のメイン領域が空・非表示でも、表示中の会話の話者マーカーを探します。ナビゲーション・メニュー・非表示の本文は取り込みません。
- ChatGPTでは既存の話者属性に加え、会話ターンに明示されたユーザー／AIの属性も読み取ります。記事の順番から話者を推測しません。
- 本文がまだない場合のみ、最大約1.2秒の範囲で表示を待って再確認します。空の会話・未送信の入力欄をレシート化することはありません。
- ポップアップにバージョンを表示します。取得できない場合はサービス名・バージョンと、会話を開く／回答の生成完了を待つ／ページを再読み込みする手順を表示します。

更新には、最新版ZIPを展開し、Chromeに読み込ませた元のフォルダーのファイルを置き換え、`chrome://extensions/` で拡張機能の再読み込み（↻）が必要です。ポップアップに「バージョン 0.4.3」が表示されることを確認し、開いているChatGPTタブも再読み込みしてください。

## 開発時

`chrome-extension` のファイルを変更したら、リポジトリ直下で `python3 scripts/package-extension.py` を実行して配布ZIPを更新してください。`python3 scripts/package-extension.py --check` で一致を確認できます。依存ライブラリの追加は不要です。
