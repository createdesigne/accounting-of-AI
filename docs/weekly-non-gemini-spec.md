# 私とAIの確定申告 — 週次プロトタイプ仕様書（Gemini API実装を除く）

- 版: v0.2 / 2026-11-12
- 対象: `createdesigne/accounting-of-AI` の既存React + TypeScript + Viteアプリ、および `chrome-extension/`
- 開発体制: **本担当 = Web UI・記録・Chrome拡張・週次会計・AIAS課題設定・分析結果の表示口**。**共同開発者 = Gemini APIの安全な呼び出し・プロンプト・分析・エラー処理（API側）**。
- 目的: 1週間で **AI利用（または手入力）→記録→確認→仕訳→週次決算→振り返り**を実際に完結させる。Geminiが未接続でも成り立つこと。
- 要注意: **本フェーズはGemini APIの実装を一切行わない**。分析は未接続のままでよく、根拠のない分析を生成しない。公式AIASの個人ランク診断を作らない。

## 1. 既存実装と非破壊方針

確認済みの構成: `src/App.tsx`、`src/ledgerPeriods.ts`、`src/conversationDraft.ts`、`src/reportSummary.ts`、`chrome-extension/`、`tests/`、`docs/`。React 19 / TypeScript / Vite / pnpm。現状には週次（月〜日）の期間切替、QR付きレシート、会話取り込み、思考帳簿の仕組みがある。

- 現在のコードを最初に読み直して変更差分を作ること。全面再構築・既存アプリの全削除は禁止。
- 既存の `ThoughtReceipt` / `IssuedThinkingReceipt`、`watashi-to-ai-thought-receipts` / `thinkingLedger` 等は異なる形式。**これらを同一データと決めつけない**。削除・サイレント移行・重複記録を避ける。
- `src/ledgerPeriods.ts` の週次境界（原則月曜00:00〜翌月曜00:00未満）は再利用し、旧週・月・年の閲覧を壊さない。
- 固定サンプルを実測・実分析・実データと表示しない。従来の機能に影響を与える改修は、事前に影響範囲を報告する。

## 2. 利用者が完了できる主フロー

1. ホームで「今週の利用状況」を表示。初回は0秒・0件（サンプルは別）。
2. **手入力**（必須）または既存Chrome拡張の会話取り込み（必須）から活動を登録。自動時間計測（後述）は別工程で実装。
3. 活動開始・終了（取れる場合）、利用秒数、取得方法（実測・手入力・補正）、活動テーマ、会話保存範囲を確認・編集。
4. 必要なら研究モードのAIASレベルを課題**開始前**に設定。未設定でも日常利用は可能。
5. 時間を仮仕訳として保存。活動テーマと費用／資産／仕掛成果物／未分類を本人が確認・確定。
6. 思考レシートを表示。Gemini未接続なら分析欄は明確に **「分析未接続／分析待ち」** とし、本人が手動で気づき・判断・学びを入力できる。API結果を捏造しない。
7. 週次画面で曜日別・活動別の秒数、件数、勘定科目、B/S・P/L相当の一覧、本人の振り返り、次週の目標を閲覧・確定。過去週にも移動できる。
8. 再読み込み後もデータが残る。後から修正・削除すると会計と週次が再計算される。

## 3. 必須画面

- **ホーム**: 週の期間、累計分秒、活動数、活動別内訳、直近のレシート、週次決算導線。サンプル非混入。
- **活動の取り込み・編集**: 会話タイトル、AIサービス、日時、利用秒数、計測方法、6分類、費用/資産等、記録許可。手入力から登録可能。
- **研究モードの課題設定**: 課題名、目標、AIASの事前設定レベル1〜5（未設定可）、AIに任せる範囲、人間が判断する点。Level 1はAI不使用課題の記録として区別。これを会話の事後能力判定に使わない。
- **思考レシート**: 科目、利用秒数、予定AIASレベル、任意の本人振り返り。API結果がまだないときはスコア空欄（0点と扱わない）。後から分析結果を表示する枠は設ける。
- **週次決算**: 7日間（月曜始まり）、総時間、科目別・日別内訳、未分類件数、仕訳明細と借貸一致、週の発見・本人の振り返り2〜3件、来週の目標、未確定/確定状態。
- **設定**: プライバシー切替、保存状況、データの書き出し（JSON）、必要なら削除、拡張機能の状態。APIキー入力・公開API送信UIを新設しない。

## 4. 費用の活動6分類と仕訳

| 利用目的 | 費用科目 |
| --- | --- |
| 悩み相談 | 相談活動費 |
| アイデアの壁打ち | 思考探究費 |
| レポート・文章作成 | 成果物利用費 |
| 調べもの・情報収集 | 情報収集費 |
| 学習・理解 | 学習活動費 |
| その他 | その他AI利用費 |

- 秒単位の非負整数を唯一の計算単位とする（秒を円や点数に換算しない）。
- 取り込み時: 借方 `AI仮受品` / 貸方 `時間拠出` （同じ秒数）。
- 確定時: 借方 `活動費用` または `成果物資産` または `仕掛成果物` / 貸方 `AI仮受品` 。不明な活動は仮受品に残す。
- 会計区分: 費用、資産、仕掛成果物、未分類。`記録総秒数 = 費用秒数 + 資産秒数 + 仕掛秒数 + 未分類秒数`。
- 全仕訳の借方合計と貸方合計が常に一致。削除・編集・再取込・週跨ぎでも不一致にしない。
- 週次のB/S・P/Lは「時間を通貨のように見立てた独自の会計モデル」。**費用を計上しただけではB/Sが自動的に釣り合うとは限らない**ため、必要な損益振替・累積時間損益を明示して理論と数式をテストする。企業の財務諸表と同じものとは表示しない。
- 今回は償却・除却・前月遡及調整など高度な処理は実装対象外。既存画面は残す。

## 5. 時間計測と会話取り込み

- 第1段階では**手入力**で週次全フローを完成させる。時間を自動計測したかのように見せない。
- 既存Chrome拡張のChatGPT / Claude / Gemini会話取得機能を壊さず、取得できた本文と取得範囲を表示。取得失敗時は明示。
- 第2段階でChatGPTに限定し、ユーザーが有効にした場合のみアクティブかつフォーカス中の時間を記録。アイドル・スリープ・タブ移動・並列タブで重複しない。実測・推定・手入力・補正を区別。
- 日付/週を跨いだ時間は各週に分割。自動計測の精度・Chrome API制約を事前確認し、テスト条件を残す。対応が難しい場合は手入力から完成版を先行する。
- 会話内容の取得・保存には利用者が確認できる導線を置く。最初の会話取得が最後の20メッセージなど一部だけのときは、全履歴のように扱わない。

## 6. プライバシー設定（会話単位）

- `full`: 利用時間と本人が許可した会話本文をローカル保存。**本担当から外部AIサービスへ送信しない**。
- `time-only`: 利用時間のみ保存。本文や分析の証拠は保存しない。
- `off`: 利用時間・会話本文のいずれも保存しない。
- 初回に既定の方針を決められ、保存前にも変更できる。後から `time-only` や `off` へ変更した場合は本文・派生した分析情報を削除し、会計側の秒数を適切に調整する。削除した本文を監査履歴に残さない。
- ローカル保存が失敗したら成功表示をしない。利用者が再試行できるようにする。

## 7. Gemini担当者との接続点（契約だけ定義し、実装しない）

**作成してよいもの**: `src/integrations/analysisContract.ts` のような**型・バージョン・受け渡し方式の提案**、分析待ち/未接続画面、サンプル用の明示したテストフィクスチャ。実装前に共同開発者と契約内容を合意する。

**作成しないもの**: API呼び出し、HTTPクライアント、Gemini SDK依存、APIプロキシ、`.env` やAPIキー導線、プロンプト、API失敗時リトライ処理、AIの採点ロジック、Geminiに基づく自動カテゴリ分類。

受け渡しの概念例（最終合意前のたたき台）:

```ts
export type AnalysisStatus = 'not-connected' | 'pending' | 'complete' | 'failed' | 'not-applicable';
export type ThoughtAnalysisV1 = {
  schemaVersion: 1;
  recordId: string;
  activityCategory: '相談' | '壁打ち' | '文章作成' | '情報収集' | '学習' | 'その他' | null;
  observedBehaviors: Array<{ kind: 'goal-setting' | 'comparison' | 'verification' | 'revision' | 'own-decision'; evidence: string | null }>;
  initiative: 0 | 25 | 50 | 75 | 100 | null;
  reasoning: 0 | 25 | 50 | 75 | 100 | null;
  criticalJudgment: 0 | 25 | 50 | 75 | 100 | null;
  thinkingChange: string | null;
  discovery: string | null;
  analysisStatus: AnalysisStatus;
};
```

- 評価は `null = 根拠不足`。0点と違う。スコアは研究独自の指標でAIAS公式基準ではない。
- `plannedAiasLevel` は課題設定データに記録し、事後の分析結果とは別扱い。AIASレベルを平均して成長スコアにしない。
- 将来的なAPI接続では `recordId` をキーに結果を受け取り、既存の原文・本人修正を上書きしない。分析側のスキーマと合わない場合は勝手に補正・捏造せずエラーを表示。
- 相方が既にAPI側の型を作っている場合は**相方の作業と競合しない命名・配置を相談し、勝手にAPI側ファイルを書き換えない**。
- 本フェーズでデモ用の分析結果を表示する場合、**「テスト用ダミー・実分析ではありません」**を明記し、本番の分析待ち画面とは分離する。

## 8. 保存スキーマ（案）

```ts
type WeeklyRecordV1 = {
  schemaVersion: 1;
  id: string; // 複数回読み込んでも増えない固有ID
  sessionId: string | null;
  recordedAt: string; // ISO timestamp
  startedAt: string | null;
  endedAt: string | null;
  activeSeconds: number;
  timeSource: 'measured' | 'manual' | 'adjusted' | 'unknown';
  aiService: 'chatgpt' | 'claude' | 'gemini' | 'other';
  privacy: 'full' | 'time-only'; // off は永続保存しない
  taskId: string | null;
  activityCategory: '相談' | '壁打ち' | '文章作成' | '情報収集' | '学習' | 'その他' | null;
  accountingDisposition: 'expense' | 'asset' | 'work-in-progress' | 'unclassified';
  analysisStatus: 'not-connected' | 'pending' | 'complete' | 'failed' | 'not-applicable';
  selfReflection: string | null;
};
```

- 別型の `TaskV1` に `plannedAiasLevel: 1|2|3|4|5|null`、課題名、目的、本人が行う判断を保存。
- 本文は別の保存領域に置く。`time-only` や削除処理では本文を確実に消す。
- 既存保存キーと別のバージョン付きキーを使う。旧データを勝手に移行しない。差分や互換性を検証し、明示的な移行仕様が必要なら別提案。
- 同じ会話/セッションの再取り込みは二重計上しない。時間の補正は元と補正値が区別できるようにする。

## 9. 週次決算と研究用の記録

- 週: 月曜日00:00〜翌月曜日00:00直前（ブラウザのローカルタイムゾーン）。日時表示に暦年と週の両端を明示する。
- 週末前でも「仮決算」「今週の振り返り」ができる。利用者が確定した後に修正した場合は再計算して再確定を促す。
- 全期間の合計、日別・科目別内訳、未分類、振り返りメモ、本人が選んだ気づき（2〜3件）、来週の小さな挑戦を表示。
- 事前AIASレベルは**課題の設計情報**として表示。個人の優劣・成長レベルとして扱わない。
- 研究用に同意のある記録だけを匿名化してJSON/CSV書出しできるように設計（会話本文は初期設定で含めない）。ただし研究倫理審査/参加同意の運用は研究者が別途設計する。

## 10. 実装フェーズと完了条件

- **Phase 0 — 調査のみ**: リポジトリ・保存キー・既存画面・拡張・テストを調査。役割分担と衝突可能性を報告。**この段階でコード変更/コミット/プッシュ禁止。**
- **Phase 1 — 週次基盤**: 新レコード型、保存、本人の手入力、冪等性、時間仕訳、週次集計、テスト。API未接続で使用可能。
- **Phase 2 — 週次UIとレシート**: ホーム、確認、レシート、週次決算、本人の振り返り、プライバシー変更。手入力2件で全体験完了。
- **Phase 3 — Chrome拡張**: 既存会話取り込みを週次レコードへ接続。ChatGPTからの利用時間計測は制約を調査してから実装・テスト（失敗時は手入力）。
- **Phase 4 — AIAS研究モード**: 課題開始前のAIAS設定、レシートとの紐づけ、根拠を空欄で扱う分析未接続UI。
- **Phase 5 — 相方との接続準備のみ**: `docs/gemini-handoff.md` にデータ契約を提案し、取り込みテスト用の**明示ラベル付き固定フィクスチャ**を用意。API実装はしない。
- **Phase 6 — 回帰・実機確認**: 型チェック、ビルド、既存/新規テスト、保存/削除、週境界、プライバシー、Chrome拡張、スマホ幅。

各Phaseの前に承認を取る。各Phaseの報告に変更ファイル・テスト結果・課題・相方と調整すべき点を含める。

## 11. 今回の「完成」の定義

**Geminiなしで、ローカルで**手入力/既存拡張から記録を追加し、保存・編集・削除・費用/資産の仕訳・過去週との切替・週次決算・本人の振り返りを一巡できる。週次時間と会計が整合し、ブラウザを更新しても消えない。「AI分析未接続」が明示され、偽の評価は一切ない。共同開発者のAPIと後から合体できる契約がある。
